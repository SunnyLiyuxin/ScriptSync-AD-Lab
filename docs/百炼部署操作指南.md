# ScriptSync 百炼部署操作指南

> 配套阅读：本文是 [README.md](./README.md) 的部署章节展开版，回答"点哪个链接、走什么流程"。

---

## 〇、概念澄清：百炼能放什么，不能放什么

| 误区 | 正解 |
| --- | --- |
| "百炼是我的服务器" | 百炼是 AI 应用托管平台（PaaS/Serverless），不能 SSH 上去装软件 |
| "所有代码都丢百炼" | 百炼高代码应用**原生支持 Python**；Node.js 协作服务端可放百炼 K8s，但放自有 ECS 更顺 |
| "Serverless 适合所有场景" | Serverless 是无状态短生命周期，**WebSocket 长连接会被冷启动打断**，协作服务端必须用 K8s 方式 |

### ScriptSync 三端的部署策略（推荐）

```
┌─────────────────────────────────────────────────────────────┐
│ 端              │ 部署位置                 │ 部署方式         │
├─────────────────────────────────────────────────────────────┤
│ 前端 Svelte     │ 百炼 K8s / Cloudflare    │ 静态文件         │
│ Python API      │ 百炼高代码应用            │ .whl 代码包      │
│ Node.js 协作    │ 百炼 K8s（或自有 ECS）   │ Docker 镜像      │
└─────────────────────────────────────────────────────────────┘
```

**MVP 建议路径**：先全部本地 `docker-compose up` 跑通 → 验证功能 → 再分步迁移上云。**不要一上来就部署**，本地跑通是基础。

## 一、第一步：开通百炼 + 创建 API Key（5 分钟）

### 1.1 开通百炼服务

1. 浏览器打开：**https://bailian.console.aliyun.com/**
2. 用阿里云账号登录（需实名认证）
3. 首次进入会弹服务协议 → 点"同意并开通"
4. 右上角选地域：
   - 国内用户选 **华北2（北京）**
   - 海外服务器选 **新加坡**

### 1.2 创建 API Key（给 Python AI 层调模型用）

1. 进入 **API Key 管理页**：**https://bailian.console.aliyun.com/?tab=model#/api-key**
2. 点右上角 **「创建 API Key」**
3. 弹窗配置：
   - **归属业务空间**：默认业务空间
   - **权限**：全部（MVP 图省事；生产可配 IP 白名单）
4. 点 **「确定」** → **立即复制**（以 `sk-` 开头，关掉弹窗就看不到了）
5. 保存到安全位置，等会儿填到 `.env` 的 `DASHSCOPE_API_KEY`

### 1.3 记下 Base URL（按你选的地域）

| 地域 | Base URL |
| --- | --- |
| 华北2（北京） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 新加坡 | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1` |

> Base URL 在百炼 SDK（dashscope）里已内置，只在用 OpenAI 兼容接口时才需要手填。

## 二、第二步：本地跑通（先别上云，先验证功能）

### 2.1 准备 .env

```bash
cd /workspace
cp .env.example .env
```

编辑 `.env`，至少填这两项：
```
JWT_SECRET=随便一串足够长的随机字符串
DASHSCOPE_API_KEY=刚才复制的 sk-xxxxx
```

### 2.2 一键启动三端

```bash
docker-compose up --build
```

启动后访问：
- 前端：http://localhost:5173
- API 文档：http://localhost:8000/docs
- 协作服务端：ws://localhost:1234（无页面，正常）

### 2.3 生成登录 token 测试

```bash
cd services/collab
# 格式：node src/issue-token.js <userId> <username> <projectId>
node src/issue-token.js user001 测试员 proj001
```

把输出的 `eyJ...` 粘贴到 http://localhost:5173 的登录框，连接 → 新建项目 → 进入编辑器。

**只有本地能跑通整个流程，再进入第三步上云。**

## 三、第三步：部署 Python API 到百炼（高代码应用）

### 3.1 创建高代码应用

1. 进入 **百炼应用中心**：**https://bailian.console.aliyun.com/?tab=app#/app-center**
2. 点 **「创建应用」** → 左侧选 **「高代码应用」**
3. 创建类型选 **「命令行创建」**（我们已有项目代码，不用模板）
4. 填应用名：`scriptsync-api` → 点 **「立即创建」**

### 3.2 选部署方式：K8s（关键，不能用 Serverless）

> **重要**：我们的 Python API 里 FastAPI 是常驻进程，且未来要承载协作 token 签发，**必须选 K8s**，不能用默认的 Serverless Function（Serverless 会冷启动，不适合长驻服务）。

1. 进入应用部署配置页
2. **「选择部署方式」** → 选 **「K8s」**
3. 首次用 K8s 会提示开通 ACK 容器服务：
   - 点提示里的链接进入 ACK 控制台 **https://cs.console.aliyun.com/**
   - 按引导开通 ACK 并完成授权（绑定 RAM 角色）
   - 回到百炼应用配置页刷新
4. **「选择部署资源」**：
   - 规格：2 vCPU / 4 GB（MVP 够用）
   - **最小实例数：1**（关键！保证毫秒级热启动、服务不中断）
   - 地域：与 API Key 同地域
5. 点 **「立即部署」**（先部署空白模板占位，下一步上传真实代码）

### 3.3 打包 .whl 并上传

百炼高代码应用要求 Python 项目打成 `.whl` 格式，用 `AgentScope-AI` 命令行工具上传。

**本地安装命令行工具**：
```bash
pip install agentscope-ai
```

**为 API 服务补一个打包配置**（在 `services/api/` 下新建 `setup.py`）：
```python
from setuptools import setup, find_packages
setup(
    name="scriptsync-api",
    version="0.1.0",
    packages=find_packages(),
    install_requires=[
        line.strip() for line in open("requirements.txt")
        if line.strip() and not line.startswith("#")
    ],
    entry_points={
        "console_scripts": [
            "scriptsync-api=app:main",
        ],
    },
)
```

**打包 + 上传**：
```bash
cd services/api
python -m build          # 生成 dist/scriptsync_api-0.1.0-py3-none-any.whl
agentscope-ai deploy --app scriptsync-api --file dist/scriptsync_api-0.1.0-py3-none-any.whl
```

> 详细打包规范参考百炼官方文档：**https://help.aliyun.com/zh/model-studio/rich-code-app-develop-guide**

### 3.4 配置环境变量

在百炼应用详情页 → **「环境变量」**，添加：
- `JWT_SECRET` = 与本地一致
- `DASHSCOPE_API_KEY` = sk-xxxxx
- `AI_MODEL` = qwen-max（精度优先，可后续切换）
- `COLLAB_WS_URL` = `ws://<协作服务端地址>:1234`（下一步部署完填）
- `DB_PATH` = `/data/scriptsync.db`
- `UPLOAD_DIR` = `/data/uploads`

### 3.5 拿到公网访问地址

部署成功后，应用详情页右侧会显示 **公网调用地址**，形如：
```
https://scriptsync-api-xxxxx.cn-beijing.fcapp.run
```

测试：浏览器打开 `<地址>/health`，应返回 `{"status":"ok"}`。

## 四、第四步：部署 Node.js 协作服务端

协作服务端是 WebSocket 长连接，**两种选择**：

### 方案 A：放百炼 K8s（与 API 同集群，比赛加分）

1. 在百炼 K8s 集群里直接部署 Docker 镜像（K8s 不限语言）
2. 把 `services/collab/Dockerfile` 构建的镜像推到 **ACR 容器镜像服务**：
   - 开通 ACR：**https://cr.console.aliyun.com/**
   - 创建个人版/企业版实例 → 创建命名空间 `scriptsync`
   - 本地构建推送：
     ```bash
     cd services/collab
     docker build -t registry.cn-beijing.aliyuncs.com/scriptsync/collab:0.1.0 .
     docker login registry.cn-beijing.aliyuncs.com
     docker push registry.cn-beijing.aliyuncs.com/scriptsync/collab:0.1.0
     ```
3. 在 ACK 控制台 **https://cs.console.aliyun.com/** → 你的集群 → **「应用 → 无状态」** → 「使用镜像创建」：
   - 镜像：`registry.cn-beijing.aliyuncs.com/scriptsync/collab:0.1.0`
   - 容器端口：1234
   - 环境变量：`JWT_SECRET`、`PORT=1234`
   - 服务类型：**负载均衡（LoadBalancer）**，勾选公网访问
4. 部署后会拿到一个公网 SLB IP，用 `ws://<IP>:1234` 作为前端连接地址

### 方案 B：放自有 ECS（更简单，调试方便）

如果你有阿里云 ECS：
```bash
# ECS 上
git clone <你的仓库>
cd scriptsync/services/collab
npm install
JWT_SECRET=xxx PORT=1234 node src/server.js
```
配安全组开放 1234 端口，用 `ws://<ECS公网IP>:1234` 作为前端连接地址。

## 五、第五步：部署前端

前端是纯静态文件，两种选择：

### 方案 A：Cloudflare Pages（零成本，推荐）
```bash
cd frontend
npm install
npm run build    # 输出 dist/ 或 build/
```
把构建产物上传到 Cloudflare Pages，绑定自定义域名。

构建时注入环境变量（Cloudflare Pages 控制台 → Settings → Environment variables）：
- `VITE_API_URL` = `https://scriptsync-api-xxxxx.cn-beijing.fcapp.run`
- `VITE_COLLAB_WS_URL` = `ws://<协作服务端地址>:1234`

### 方案 B：百炼 K8s
构建前端镜像（基于 nginx）推到 ACR，在 ACK 同样以无状态部署，Service 走负载均衡。

## 八、常见坑

1. **Serverless vs K8s 选错**：协作服务端和常驻 API 都不能用 Serverless，会冷启动断连。**必须 K8s，最小实例数≥1**。
2. **API Key 没复制就关弹窗**：百炼 API Key 关弹窗后只能看脱敏的，**必须当场复制**，丢了只能重建。
3. **JWT_SECRET 不一致**：Python API 和 Node.js 协作服务端的 `JWT_SECRET` **必须完全一致**，否则 token 互相验不过。
4. **地域不一致**：API Key、ACK 集群、ACR 镜像、RDS 最好同地域，跨地域有延迟和费用。
5. **WebSocket 被网关拦**：百炼/SLB 默认支持 WebSocket，但如果套了 CDN 要确认 CDN 支持 ws（Cloudflare 默认支持）。
6. **本地跑通再上云**：上云前一定先 `docker-compose up` 本地验证，避免云上调试困难。

## 九、推荐执行顺序

1. ✅ 本地 `docker-compose up` 跑通（含 AI 调用）
2. ✅ 创建百炼 API Key
3. ✅ 部署 Python API 到百炼 K8s（.whl）
4. ✅ 部署 Node.js 协作服务端（百炼 K8s 镜像 或 自有 ECS）
5. ✅ 部署前端（Cloudflare Pages）
6. ✅ 回填各端地址到前端环境变量，重新构建部署
7. ✅ 端到端联调
