# ScriptSync 功能总览

> 本文档汇总 ScriptSync 当前已实现的所有功能，按「主功能 → 子功能 → 实现状态 → 技术细节」层级展开，详细程度对齐「实时同步 / 自动保存」节，作为后续阶段化开发的基线参照。
>
> 状态标记说明：
> - **[已满足]**：功能完整可用，已通过联调。
> - **[需补全]**：已有骨架/部分实现，但存在缺口，需在后续阶段补完。
> - **[缺失]**：尚未实现，列入后续阶段计划。

## 一、实时协作（Real-time Collaboration）

### 1.1 文档同步

- **[已满足]** Yjs CRDT 自动合并无冲突。
  - 每个项目房间对应一个 `Y.Doc`，顶层结构为 `YjsDocStructure`（[types/project.ts:81-88](file:///workspace/frontend/src/types/project.ts)）：`meta`（项目元数据）/ `scriptInfo`（ASS 脚本信息）/ `styles`（样式数组）/ `events`（核心字幕数组）/ `comments`（按 eventId 索引的批注 Map）/ `assignments`（段落分配数组）。
  - 所有编辑操作经 [yjs-operations.ts](file:///workspace/frontend/src/lib/collaboration/yjs-operations.ts) 封装：`createEvent` / `updateText` / `updateTime` / `transitionStatus` / `importEvents` / `assignEvent` / `addComment` / `getComments`，全部基于 `Y.Array` 与 `Y.Map` 的原子事务，CRDT 保证多人并发无冲突。
  - 初始化入口 [yjs-setup.ts](file:///workspace/frontend/src/lib/collaboration/yjs-setup.ts)，通过 `WebsocketProvider` 连接协作服务端，`observeDeep` 订阅变更并回填到 Svelte 响应式状态。

### 1.2 在线用户感知

- **[已满足]** awareness 实时显示在线用户头像。
  - [awareness-lock.ts:94-106](file:///workspace/frontend/src/lib/collaboration/awareness-lock.ts) `getOnlineUsers` 遍历 `awareness.getStates()`，聚合 `user` 字段（userId / username / color / clientId）。
  - 前端 `TimelineEditor.svelte` 通过 `provider.awareness.on('change')` 订阅，实时刷新顶部在线头像列表与每行锁持有者标识。
  - 颜色由 ` AwarenessState.color` 字段统一分配，避免视觉冲突。

### 1.3 行级锁

- **[需补全]** 行级锁：当前有 [awareness-lock.ts](file:///workspace/frontend/src/lib/collaboration/awareness-lock.ts) 但未在编辑时自动触发，需在 `editingId` 变化时自动加锁/解锁。
  - 已实现：`lockEntry(provider, entryId)` 写入 `awareness.cursor = { entryId, typing: true }`；`unlockEntry(provider)` 清空；`getLockHolder(provider, entryId, myUserId)` 返回他人锁持有者 userId。
  - 缺口：`TimelineEditor.svelte` 的 `startEdit` / `saveEdit` / `cancelEdit` 调用链中**未调用** `lockEntry` / `unlockEntry`，导致锁机制处于「有接口无触发」状态。需在 `editingId` 变化的 `$effect` 中自动加锁，编辑结束（保存/取消/失焦/页面卸载）时自动解锁。
  - 缺口：离开页面时未兜底解锁，可能导致「幽灵锁」——需在 `onDestroy` 与 `visibilitychange` 事件中清理。

### 1.4 他人光标位置

- **[需补全]** 他人光标位置显示（awareness 已有用户列表，但未广播光标位置）。
  - 已实现：`AwarenessState.cursor` 类型已定义 `{ entryId, typing }`（[types/project.ts:67-70](file:///workspace/frontend/src/types/project.ts)），`lockEntry` 写入的正是此字段。
  - 缺口：前端表格行未读取他人 `cursor.entryId` 渲染「某某正在此行」的悬浮标记，仅读取了 `lockHolder` 用于拦截编辑。需补全：在每行右上角渲染当前光标持有者的彩色头像气泡，鼠标悬停显示用户名。

### 1.5 播放状态广播（演练态）

- **[已满足]** `broadcastPlayback` / `subscribePlayback` 已实现（[awareness-lock.ts:55-89](file:///workspace/frontend/src/lib/collaboration/awareness-lock.ts)），用于演练态一人控制众人跟随。
  - 编辑态默认各自独立播放，不广播；演练态由 `RehearsalMode.svelte` 切换为同步模式。

## 二、自动保存（Auto-save）

### 2.1 实时同步链路

- **[已满足]** Yjs 通过 WebSocket 持续同步到协作服务端。
  - 前端每次 `Y.Array` / `Y.Map` 变更即触发 y-websocket 协议的 update 消息，二进制 diff 增量传输，带宽占用极低。
  - 服务端 [server.js](file:///workspace/services/collab/src/server.js) 收到 update 后广播给同房间其他连接，并触发 `writeState` 钩子（当前为 TODO，未真正落盘）。

### 2.2 服务端持久化

- **[已满足]** 服务端定期持久化（[snapshot.js](file:///workspace/services/collab/src/snapshot.js)）。
  - 默认每 5 分钟（`SNAPSHOT_INTERVAL_MS = 5 * 60 * 1000`）调用 `createSnapshot`，用 `Y.encodeStateAsUpdate(doc)` 编码全量二进制，写入 `/tmp/snapshots/<projectId>/<versionId>.yjs`，元数据（id / 时间 / 创建人 / label / size）追加到 `meta.json`。
  - 快照触发时机：定时 + 手动（HTTP `/snapshot/:projectId` POST）+ 关键节点（如审批通过批量转 locked 时）。

### 2.3 断网恢复

- **[已满足]** 断网重连自动恢复（y-websocket 内置）。
  - `WebsocketProvider` 内置指数退避重连，重连后通过 `sync-step1` / `sync-step2` 协议交换缺失 update，自动追平本地与服务端状态差异。
  - 本地离线期间的编辑暂存于内存 `Y.Doc`，重连后批量推送，无数据丢失。

### 2.4 版本快照管理

- **[已满足]** 版本快照手动创建 + 回滚。
  - 创建：[VersionHistory.svelte](file:///workspace/frontend/src/components/VersionHistory.svelte) 调 HTTP `POST /snapshot/:projectId`，服务端 `snapshot.js:202-260` 生成快照并返回元数据。
  - 列表：HTTP `GET /snapshot/:projectId` 返回 `meta.json` 全部记录。
  - 回滚：HTTP `POST /snapshot/:projectId/:versionId/rollback`，`snapshot.js:127-178` 采用「文档替换」策略——构造新 `Y.Doc` 应用快照 bytes，`oldDoc.conns.clear()` 防 y-websocket 误删同名文档，关闭旧连接促使客户端重连到回滚后状态。
  - **[需补全]** Python API 层 `/api/projects/{id}/versions/{vid}/rollback`（[app.py:698-705](file:///workspace/services/api/app.py)）仅返回 `rollback_requested` 标记，未实际触发回滚——前端 VersionHistory 实际走的是 Node 协作服务端的 `/snapshot` 端点，Python 端点为废弃路径，需统一或移除。

### 2.5 实时保存开关

- **[已满足]** 编辑器提供「实时保存」开关（`TimelineEditor.svelte` `realtimeSave` 状态）。
  - 开启：每次 `updateText` 即时写入 Yjs，秒级同步全员。
  - 关闭：累积 `pendingChanges` 到本地，点击「保存我负责的全部」时 `saveAllMine` 批量提交，适合弱网或集中校对场景。

### 2.6 持久化层缺口

- **[需补全]** `server.js` 的 `bindState`（行 62 `// TODO: 从 OSS 恢复文档快照`）与 `writeState`（行 66 `// TODO: 将 ydoc 快照写入 OSS`）未实现。
  - 当前服务重启后 `docs` Map 清空，已连客户端的编辑仍能同步到内存，但新加入者拿不到历史文档（仅能拿到定时快照恢复的部分）。
  - 生产前必须补全：bindState 从 OSS 拉取最新快照加载到 Doc；writeState 防抖写回 OSS。
